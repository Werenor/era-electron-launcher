# Era-Electron启动器

独立的 Windows 第三方启动器：集中管理本地 Era-Electron 游戏与多个引擎版本，选择游戏后启动，退出时清理临时引擎。

## 使用

下载 Windows x64 发布包，完整解压，双击 **StartGame.exe**。需要 Windows 10/11 与系统 .NET Framework 4.8；无需安装 Python，无需管理员权限。发行包不附带引擎或游戏。

1. 打开“引擎管理”，通过“引擎官方发布页”在浏览器访问官方站点，下载并解压需要的版本。
2. 点击“登记引擎目录”，可登记多个版本。
3. 导入包含 `ere/main.js` 或打包入口的游戏目录。
4. 为游戏选择引擎。游戏名称、输入模式与可用的窗口选项在编辑后自动保存。
5. 点击“启动游戏”。启动器保持打开，显示运行日志；游戏退出后清理临时引擎并返回就绪状态。

## 多版本与扩展

标准启动不按版本号设白名单，原版引擎不会被修改。启动器检测安装包中的版本并允许每个游戏独立选择。现有 Era-Electron 使用独立引擎用户配置的 `last` 路径打开选定游戏；如未来引擎改变这一启动约定，需增加对应适配。

**引擎版本支持与输入扩展适配是两回事。** keystate 1.1.0 和临时窗口参数目前为已验证的原版 5.1.0 提供。其他版本使用标准启动，窗口由游戏自己的配置决定，界面不会套用不匹配的补丁。后续可在保留其他版本的同时增加适配。

支持游戏列表搜索、导入、复制启动配置、移出列表、引擎校验、停止游戏、日志文件与目录入口。移出列表不删除游戏或存档。

## 数据与退出清理

- 引擎与游戏目录保存为绝对路径，记录旧路径基准及最近使用的启动器目录；换文件夹运行新版启动器仍沿用原登记。
- 引擎目录失效时，只在已知目录及其有限相邻位置检查；仅在找到唯一一份归档SHA-256相同的引擎时自动恢复。多个匹配、缺少指纹或引擎版本已变化时，请使用“重新定位引擎”，保留原有游戏绑定。不会扫描整个磁盘或擅自选择另一版本。
- 游戏目录失效时，启动前提示重新选择原游戏根目录；不会猜选其他游戏或复制存档。实时按键模式不兼容新引擎时明确提示，不自动改成标准输入。
- 更新启动器前先关闭所有启动器窗口，再完整解压同一版本发布包。不要只替换StartGame.exe或混用其他构建的KeyStateProbe.exe；组件校验失败时会注明具体文件。

- 配置：当前用户 LocalAppData/PortArcadeLauncher/launcher.json，保存时保留备份。该历史目录名用于兼容早期版本。
- 每个启动配置的引擎用户数据保存在 `instances/<ID>/profile`。
- 日志保存在 `logs`，包括启动记录和引擎日志快照。
- 引擎运行在 `sessions/<随机ID>` 的临时副本，关闭后清理。异常残留会在下次启动时检查。
- 存档仍在游戏目录。复制启动配置不会复制游戏或存档；同一游戏目录不允许并发启动。
- 有游戏运行时关闭启动器，会询问是否停止并清理。普通设置直接自动保存，没有“保存设置”按钮。临时空白的游戏名称等无效输入不会覆盖最后一次有效配置。

keystate 采用 Electron 输入事件与 Windows 原生松键校验，修复真实环境可能缺失的 keyup；只在游戏启用捕获且窗口有焦点时运行原生组件，退出或失焦停止。不安装服务或全局键盘钩子。

## 构建

在安装有 .NET Framework 4.x 编译器的 Windows 上运行：

```powershell
.uild.ps1
```

脚本编译启动器和原生组件，运行检查，生成 `dist/Era-Electron-Launcher-v0.5.0-win-x64.zip` 与 SHA256SUMS.txt。构建和运行均无需下载原版引擎，无 Python 依赖。

```powershell
.\dist\Era-Electron-Launcher-v0.5.0-win-x64\StartGame.exe --self-test C:\Temp\launcher-checks.txt
```

源码包括图形界面、配置存储、进程生命周期、ASAR 适配器、keystate 与原生组件。`build.ps1` 从源码生成组件校验值。

## v0.5.0

窗口默认使用游戏自己的尺寸、字号和最大化配置。勾选“自定义窗口”才应用启动器参数；取消后恢复游戏原配置，保留自定义数值供以后使用。旧配置未指定该选项时同样采用游戏原始窗口。自定义窗口仍需要已适配的引擎。

“下载引擎”读取官方发布列表；HTTPS ZIP 直链可直接下载、解压、验证并登记，网盘链接转到浏览器，下载 Windows ZIP 后点击“安装下载的 ZIP”。安装目录由用户选择，不覆盖已有引擎。当前官方5.1.0下载链接为MEGA网盘。ZIP会检查路径越界、符号链接、条目和解压大小限制，失败清理安装暂存。

“检查启动器更新”查询GitHub正式Release，发现新版后显示版本和发布说明，可打开发布页下载。网络异常、限流会显示错误。不自动覆盖运行中的启动器。游戏下载本版未实现。

安装成功后自动清理使用的 ZIP 安装包和解压暂存（包括手动选择的 ZIP）。安装失败保留手动选择的原安装包以便重试，直链下载的未完成文件会清理。安装进行中暂不允许退出启动器，以便完成安装和清理。

## 独立插件声明（旧格式，继续兼容）
游戏根目录 ere.launcher.json：
```json
{"plugins":[{"id":"ere-keystate","source":"github","repository":"Werenor/ere-keystate","fallback":true}]}
```
source/repository/id 为插件身份。缺失时弹窗选择下载、兼容运行或取消；fallback 省略或 false 时不允许兼容运行。首次下载从仓库的最新正式 Release 获取 win-x64.zip，缓存于 LocalAppData/PortArcadeLauncher/plugins/github/发布者/仓库/id。缓存插件不会因启动器更新自动改变。插件包需带 plugin.json、身份、文件 SHA-256 和代码替换锚点；按锚点唯一匹配应用，不限制引擎版本号。只修改临时副本。旧的手动实时模式保留兼容旧游戏，声明插件的游戏优先采用独立插件。


## 游戏列表与插件页

不再提供输入模式选择。游戏列表显示上次启动时间和从 GameBase 获取的版本号，最近启动的游戏在前；版本无法读取时留空。插件页检查当前游戏的声明，显示插件名称、适用版本号和未安装／未启用／已启用状态；发布来源与详细检查结果在悬浮提示中显示，勾选决定该游戏是否启用插件。安装与启用分别操作，选择自动保存。首次打开插件页检查，声明或游戏更换后重新检查；启动前始终复查。缺失、停用、损坏或不匹配的声明插件会提醒；不支持兼容运行的插件未加载时阻止启动。旧输入模式设置不再影响插件加载。

## 游戏仓库与更新声明

游戏根目录 `ere.launcher.json`：

```json
{
  "game": {
    "repository": "https://gitgud.io/ereal/game",
    "version": "0.8.0",
    "branch": "main"
  },
  "plugins": []
}
```

`branch` 为发布分支，省略时默认 `main`。作者在发布分支更新声明版本并推送代码即可，无需创建游戏 Release。支持 GitHub、GitGud。先解析分支当前提交 SHA，再从该 SHA 读取声明并生成同一 SHA 的源码 ZIP 链接。远程声明必须属于同一个仓库。只比较声明版本，分支提交变化但版本未变时不提示新版。

左侧优先显示声明版本。无法比较的版本仅显示差异，不猜测先后。检查是只读操作，不下载、解压、覆盖或搬移游戏、sav、存档或玩家设置；确认后仅在浏览器打开固定 SHA 下载链接。网络错误、缺失分支或声明显示检查失败，不冒充已是最新。当前不执行游戏原地覆盖更新。

启动器自身和独立插件仍使用各自的 GitHub Releases。

## 统一声明格式（v0.7.0）

新声明统一使用完整HTTPS仓库地址和整数 `schemaVersion: 1`，不再使用 `source`。详见[格式规范](docs/manifest-format.md)、[游戏 Schema](schemas/ere.launcher.schema.json)和[插件 Schema](schemas/plugin.schema.json)。旧的v0.6.0启动器不支持新插件声明，需先升级启动器再分发新声明。

升级顺序：先将启动器整包更新到v0.7.0，再更新游戏。旧启动器可使用“检查启动器更新”打开新版Release；新启动器继续支持旧游戏声明，原插件缓存与每游戏启停设置不变。保留自己的游戏目录、存档及启动器配置。
